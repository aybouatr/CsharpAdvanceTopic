==========================================================> Reflection <====================================================


1. -> Reflection is a powerful feature in C# that allows you to inspect and manipulate the metadata of types at runtime.
      It provides the ability to access information about assemblies, modules, types, and members.

   -> can used MenberInfo, MethodInfo, PropertyInfo, FieldInfo, ConstructorInfo, etc. to access information about types and their members.
   -> can used to create instances of types, invoke methods, access properties and fields, and even modify the behavior of types at runtime.
   -> Reflection can be used for various purposes, such as:
      - Dynamically loading assemblies and types
      - Creating instances of types at runtime
      - Invoking methods and accessing properties/fields dynamically
      - Implementing custom serialization/deserialization logic
      - Building frameworks and libraries that require dynamic behavior

=========================================================> Custom Attributes <====================================================


1. -> Custom attributes are user-defined attributes that you can create to add metadata to your code. 
      They allow you to define your own attributes with specific properties and behavior.

   -> To create a custom attribute, you need to define a class that inherits from the System.Attribute class. 
      You can then apply this custom attribute to classes, methods, properties, or other code elements.

   -> Custom attributes can have properties and fields that store additional information. 
      You can access this information at runtime using reflection.

   -> Custom attributes are commonly used for various purposes, such as:
      - Providing additional information about code elements
      - Implementing custom validation logic
      - Controlling the behavior of frameworks and libraries
      - Enhancing code readability and maintainability


=========================================================> Mutable types VS Immutable Types <====================================================


1. -> Mutable types are types whose state can be modified after they are created. 
      Examples of mutable types in C# include classes, arrays, and collections.

   -> Immutable types are types whose state cannot be modified after they are created. 
      Examples of immutable types in C# include strings, tuples, and records.

   -> The main difference between mutable and immutable types is that mutable types can be changed, while immutable types cannot. 
      This has implications for how you work with these types in your code, especially when it comes to concurrency and thread safety.


=========================================================> Generics <====================================================


1. -> Generics in C# allow you to define classes, methods, and data structures that can work with any data type while providing type safety at compile time. 
      They enable you to create reusable code that can operate on different types without sacrificing performance.
   
   -> With generics, you can create a single class or method that can handle multiple data types, eliminating the need for code duplication. 
      This promotes code reusability and maintainability.

   -> Generics are commonly used in collections (e.g., List<T>, Dictionary<TKey, TValue>), as well as in custom classes and methods that require flexibility in handling different types of data.

      It is used to manage system settings, user preferences, and application configurations.
   -> In C#, you can interact with the Windows Registry using the Microsoft.Win32 namespace, which provides classes such as RegistryKey and RegistryValueKind to read, write, and manipulate registry keys and values.

      - Managing user-specific and system-wide settings

  ==========================================================> String Builder <====================================================

  1. -> StringBuilder is a class in the System.Text namespace that provides a mutable string-like object. 
        It is designed for scenarios where you need to perform multiple string manipulations, such as concatenation, insertion, or replacement, without creating multiple string instances.
   
   -> In C#, strings are immutable, meaning that any modification to a string creates a new instance. 
       This can lead to performance issues when performing extensive string operations. 
       StringBuilder allows you to modify the same instance without creating new ones, improving performance.
    -> Common operations with StringBuilder include:
        - Appending strings using the Append method
        - Inserting strings at specific positions using the Insert method
        - Replacing substrings using the Replace method
        - Removing characters or substrings using the Remove method
        - Converting the StringBuilder to a string using the ToString method
    -> Using StringBuilder can significantly improve performance when working with large or complex string manipulations in your applications.

    ======================================================> Cryptography <====================================================

    1. -> Cryptography is the practice of securing information by transforming it into an unreadable format, known as encryption,
          and then converting it back to its original form, known as decryption. 
          It is used to protect sensitive data from unauthorized access and ensure confidentiality, integrity, and authenticity.
    
    -> In C#, you can use the System.Security.Cryptography namespace, which provides a variety of classes for implementing cryptographic operations, such as hashing, encryption, and digital signatures.
    
    -> hashing algorithms (e.g., SHA256, MD5) are used to generate a fixed-size hash value from input data, which can be used for data integrity verification.
    
    -> Symmetric encryption algorithms (e.g., AES, DES) use the same key for both encryption and decryption, while asymmetric encryption algorithms (e.g., RSA) use a pair of keys (public and private) for encryption and decryption.
    
    -> asymmetric encryption is often used for secure communication and digital signatures, while symmetric encryption is typically used for encrypting large amounts of data due to its efficiency.
    
    -> diff between symmetric and asymmetric encryption:
       - Symmetric encryption uses the same key for both encryption and decryption, while asymmetric encryption uses a pair of keys (public and private).
       - Symmetric encryption is faster than asymmetric encryption, making it suitable for encrypting large amounts of data, while asymmetric encryption is typically used for secure communication and digital signatures.


  ======================================================> ovveriding operator <====================================================

  1. -> Operator overloading is a feature in C# that allows you to define custom behavior for standard operators (e.g., +, -, *, /) when applied to instances of your classes or structs. 
        This can make your code more intuitive and easier to read when working with custom types.
    -> To overload an operator, you need to define a static method in your class or struct with the appropriate signature for the operator you want to overload. 
       The method should return the result of the operation and take the necessary parameters.
    -> Common operators that can be overloaded include:
       - Arithmetic operators: +, -, *, /, %
       - Comparison operators: ==, !=, <, >, <=, >=
       - Logical operators: &&, ||, !
       - Increment and decrement operators: ++, --
    -> When overloading operators, it is important to ensure that the behavior is consistent with the expected semantics of the operator and that it does not lead to confusion or unintended consequences in your code.
    
  ======================================================> multithreading && parallel programming && thread vs process <====================================================
   
   process : A process is an instance of a program that is being executed. It has its own memory space and resources, 
              and multiple processes can run concurrently on a system.
   
   thread : A thread is a unit of execution within a process. It shares the same memory space and resources as other threads in the same process,
             allowing for concurrent execution of tasks within a single process.
   
   process vs thread : A process is an independent program with its own memory space, while a thread is a smaller unit of execution within a process that shares the same memory space.
